# AI 게이트웨이

## Decisions

- 문구 생성이든 사진 보정이든, 전시 제작에 쓰는 모든 AI 모델 호출은 Vercel AI Gateway를 기본 경로로 한다. OpenRouter는 기본 경로가 실패했을 때 쓰는 대체 경로다.
- 호출 형식과 모델 식별자는 기본 경로인 Vercel AI Gateway 문서를 기준으로 맞춘다.
- 모델 공급자의 API를 코드에서 직접 호출하지 않는다. 공급자 교체는 게이트웨이 설정에서 처리한다.
- AI는 사용자가 생성·재생성이나 보정을 명시적으로 요청할 때만 호출한다. 전시 확정, 이미 저장된 문구·사진 조회, 목록 조회, 전시 감상과 공유 상태 변경에는 호출하지 않는다.

## Boundaries

- 어떤 모델을 쓸지는 이 결정에서 고정하지 않는다. 각 작업의 스펙이 바꾸기 쉬운 기본값으로 정한다. 공급자와 모델을 바꿔 끼울 수 있게 두는 것이 이 결정의 목적이다.
- 프롬프트 내용과 생성 규칙은 각 작업의 스펙에서 정한다.

## Why

문구든 사진이든 AI로 만드는 결과물은 이 제품 경험의 핵심이라 한 공급자의 장애나 정책 변경이 곧 서비스 중단이 된다. 게이트웨이를 앞에 두면 자격증명과 비용 추적을 한 곳에서 관리하면서 공급자를 바꿔 끼울 수 있다.

확정된 전시는 사용자의 기록이다. 저장된 문구와 사진을 그대로 보여주면 감상할 때 불필요한 생성 비용이 들지 않고, AI 장애가 이미 만든 전시의 감상을 막지 않는다.

두 게이트웨이는 역할이 거의 같아서 기본과 대체를 분명히 나눈다. 둘을 동등하게 쓰면 호출 형식과 모델 식별자가 갈라지고 검증할 경로가 두 배가 된다. Vercel을 기본으로 둔 것은 이 프로젝트가 Next.js이고 배포와 자격증명 관리가 같은 울타리 안에서 끝나기 때문이다.

## Reconsider when

- Vercel AI Gateway가 필요한 모델이나 기능을 제공하지 못하는 상황이 반복될 때
- 대체 경로가 실제로 쓰이지 않아 두 경로를 유지할 이유가 사라질 때
- 배포 플랫폼이 Vercel이 아니게 될 때. 기본 경로를 Vercel로 고른 근거가 사라진다.

## Still-rejected alternatives

- 모델 공급자의 API를 직접 호출하는 방식 — 공급자 장애나 정책 변경이 그대로 서비스 중단이 되고, 자격증명 관리와 비용 추적을 직접 만들어야 한다.
- 두 게이트웨이를 동등하게 쓰는 방식 — 호출 형식과 모델 식별자가 갈라지고 검증 범위가 두 배가 된다.
