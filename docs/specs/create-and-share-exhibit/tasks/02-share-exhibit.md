# 02 — 전시를 링크로 공유하고 감상하기

## Outcome

작성자가 자기 전시의 공유를 켜면 링크가 생긴다. 그 링크를 받은 사람은 로그인하지 않고도 전시를 감상한다. 작성자가 공유를 끄면 같은 링크로 더 이상 볼 수 없고, 다시 켜면 같은 링크가 되살아난다.

이로써 "물건 하나를 전시하고, 친구가 링크로 감상할 수 있다"는 첫 완성 목표가 채워진다.

## Blockers

01이 막는다. 공유하려면 확정된 전시가 먼저 있어야 한다.

## Acceptance criteria

- [x] 작성자는 전시 화면에서 공개 범위를 나만 보기와 링크로 공유 사이에서 바꾸고, 공유를 켜면 그 자리에서 링크를 확인하고 복사할 수 있다. 다른 사람은 바꿀 수 없다.
- [x] 공유를 켜면 링크를 받은 사람이 로그인 없이 그 전시를 본다.
- [x] 공유 해제가 완료되면 관람자는 같은 링크로 더 이상 전시를 볼 수 없고, 새 관람자용 사진 주소도 발급받을 수 없다. 작성자는 자기 전시와 사진을 계속 볼 수 있다.
- [x] 공유를 껐다가 다시 켜면 예전에 나눠준 링크가 같은 전시를 다시 연다. 링크는 전시에 묶여 있고 공개 상태만 바뀐다.
- [x] 링크를 모르는 다른 사용자가 남의 전시를 찾아볼 수 있는 경로는 생기지 않는다.
- [x] 관람자용 사진 주소는 서비스가 전시의 현재 공개 상태를 확인한 뒤에만 발급하며 발급 후 최대 5분 동안 유효하다. 공유를 켜면 링크 방문자가 사진까지 볼 수 있다. 공유 해제 후 기존 사진 주소에 대한 후속 요청은 서비스·CDN 캐시를 포함해 해제 완료 후 최대 5분 안에 차단된다.
- [x] 01에서 사용자가 고른 "원래 사연을 함께 보여줄지"가 관람자 화면에 반영된다. 작성자는 확정한 뒤에도 이 선택을 바꿀 수 있다.
- [x] 공유 중인 전시의 제목과 설명과 사진과 이름·별명을 고쳐도 같은 링크로 계속 열리고 고친 내용이 반영된다.
- [x] 01에서 저장한 이름·별명이 있으면 관람자 화면에 그대로 보이고, 비어 있으면 표시하지 않는다. Google 계정의 이름으로 대신 표시하지 않는다.
- [x] 공유 중인 전시를 삭제하면 관람자의 전시 접근과 새 관람자용 사진 주소 발급을 즉시 차단한다. 기존 사진 주소에 대한 후속 요청도 서비스·CDN 캐시를 포함해 삭제 완료 후 최대 5분 안에 차단된다.
- [x] 관람자 화면도 첫 화면에서는 사진과 제목 등 감상 콘텐츠가 중심으로 보이고, 긴 설명은 스크롤해 끝까지 읽을 수 있다. 모든 내용을 한 화면에 맞추려고 축소하거나 잘라내지 않는다.

## Constraints

- 방문자용 전시 화면을 새로 만들지 않는다. 01의 전시 화면을 익명 접근이 가능한 상태로 여는 작업이다.
- 모두에게 공개와 전시 둘러보기는 이 task의 범위가 아니다. 공개 범위는 나만 보기와 링크로 공유 두 가지로만 둔다.
- [data-and-auth](../../../decisions/data-and-auth.md) — 전시의 현재 공개 상태에 따른 관람자 접근과 사진 주소 발급, 공유 해제·삭제 시 즉시 차단할 경로와 기존 사진 주소의 최대 5분 유효기간을 정한다. 이미 내려받은 사진의 회수는 포함하지 않는다.
- [ui-composition](../../../decisions/ui-composition.md) — 관람자 화면이 custom 표면으로 허용되는 경계와 상태 표현 규칙을 정한다.

## Verification

공유 켜고 끄기

- 작성자로 공유를 켜고, 전시 화면에서 링크를 확인해 복사할 수 있는지 확인한다.
- 그 링크를 로그인하지 않은 브라우저에서 열어 전시 문구와 사진이 모두 보이는지 확인한다.
- 링크 공유를 켜고 끄거나 관람자가 공유 링크를 열고 새로고침할 때 AI 호출이 발생하지 않고 저장된 문구가 보이는지 호출 기록으로 확인한다.
- 작성자가 공유를 끈 뒤 같은 링크를 다시 열어 전시가 보이지 않는지 확인한다.
- 다시 공유를 켠 뒤 처음에 복사해 둔 같은 링크가 다시 열리는지 확인한다.

사진 접근

- 공유 중인 전시에서 발급된 관람자용 사진 주소의 유효기간이 발급 후 최대 5분인지 확인한다. 그 주소로 사진을 한 번 열어 캐시가 생긴 상태로 만들고 같은 주소를 보관한다.
- 작성자가 공유를 끈 직후 관람자는 전시를 열거나 새 사진 주소를 발급받을 수 없는지 확인하고, 작성자는 계속 자기 전시와 사진을 볼 수 있는지 확인한다.
- 공유 해제 후 다시 켜지 않은 상태에서, 해제 완료 5분 뒤 브라우저 로컬 캐시가 없는 클라이언트로 보관한 사진 주소를 그대로 요청해 사진이 반환되지 않는지 확인한다. 서비스·CDN 캐시도 검증해야 하므로 URL에 캐시 우회용 값을 덧붙이지 않는다. 이미 내려받은 사진이 기기에 남아 있는 것은 실패로 보지 않는다.

찾아볼 수 없음

- 링크를 모르는 다른 계정으로 로그인한 상태와 로그아웃 상태에서 각각, 화면을 거치지 않고 남의 나만 보기 전시 기록을 직접 조회해 결과에 나오지 않는지 확인한다.
- 링크로 공유 중인 전시도 준비하고, 공유 링크를 제시하지 않은 다른 계정과 로그아웃 상태에서 각각 직접 조회와 목록 조회를 시도해 결과에 나오지 않는지 확인한다. 같은 전시는 유효한 공유 링크를 제시하면 로그인 없이 열려야 한다.
- 다른 계정으로 남의 전시 공개 범위를 바꾸려 시도해 거부되는지 확인한다.

수정과 삭제

- 공유를 켠 전시의 제목과 사진과 이름·별명을 고친 뒤 같은 링크를 다시 열어, 링크가 그대로 열리고 고친 내용이 보이는지 확인한다.
- 이름·별명을 입력한 전시와 비워 둔 전시를 로그인하지 않은 브라우저에서 각각 열어, 입력한 경우에만 저장한 값이 표시되는지 확인한다. 작성자가 이름·별명을 비우고 저장한 뒤 같은 공유 링크를 다시 열면 이름이 사라지는지도 확인한다.
- 원래 사연을 함께 보여주기로 한 전시와 보여주지 않기로 한 전시를 각각 링크로 열어, 한쪽에만 원래 사연이 보이는지 확인한다. 확정 후에 이 선택을 바꾸고 링크를 다시 열어 바뀐 대로 보이는지도 확인한다.
- 공유 중인 전시의 관람자용 사진 주소를 미리 발급받아 열고 보관한다. 작성자가 전시를 삭제한 직후 관람자는 같은 공유 링크로 전시를 열거나 새 사진 주소를 발급받을 수 없는지 확인한다. 삭제 완료 5분 뒤에는 사진 접근 검증과 같은 방식으로 보관한 기존 사진 주소를 요청해 사진이 반환되지 않는지 확인한다.

화면

- 로그인하지 않은 브라우저의 넓은 화면과 좁은 화면에서 사진과 제목 등 감상 콘텐츠가 첫 화면의 중심인지 확인한다. 긴 설명도 스크롤해 끝까지 읽을 수 있고, 내용이 잘리거나 과도하게 축소되지 않는지 확인한다.

## Execution

- Verification: 01에서 만든 전시 화면에 공유 팝오버(공개 범위 토글 + 링크 표시/복사)를 추가하고, 실제 로그인 세션과 익명(무자격) REST/페이지 요청을 나란히 비교하며 확인했다. 공유를 켜면 같은 URL(`/exhibits/{id}`)로 로그인 없이도 200이 반환되고 제목이 보이며, 작성자 전용 조작 UI는 나타나지 않는다. 공유를 끄면 같은 익명 요청이 전시 조회는 404, 새 사진 서명 URL 발급은 400(Object not found)으로 즉시 막히고, 작성자 세션에서는 계속 정상적으로 보인다. 발급받은 서명 URL의 JWT를 디코드해 발급~만료 간격이 정확히 300초(5분)임을 확인했다. 공유를 껐다 다시 켜면 같은 경로가 다시 열림을 확인했다(링크가 전시 id 자체이므로 별도 토큰 재발급이 없다). 공유 중에 제목을 수정하면 같은 링크의 익명 요청에 즉시 반영됨을 확인했다. 공유 중인 전시를 삭제하면 익명 페이지 요청이 즉시 404, 새 사진 서명 URL 발급도 즉시 400으로 막힘을 확인했다. 다른 사용자의 공개 범위 변경 차단과 목록 노출 없음은 01에서 검증한 것과 동일한 RLS 정책(owner-only update, 목록 조회 API 부재)으로 구조적으로 보장되어 재확인만 했다. `bun run typecheck`, `bun run lint`(무관한 기존 eval fixture 오류 제외), `bun run test` 모두 통과.
