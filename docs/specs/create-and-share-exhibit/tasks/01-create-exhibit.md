# 01 — 전시를 만들어 내 전시관에 보관하기

## Outcome

로그인한 사람이 물건 사진과 짧은 사연을 넣으면 AI가 전시 제목 후보와 설명을 제안한다. 사용자가 그 문구를 고르고 고쳐 확정하면 전시 한 점이 나만 보기 상태로 내 전시관에 남는다. 작성자는 나중에 그 전시를 다시 열어보고, 내용을 고치고, 지울 수 있다.

이 시점에는 아직 남에게 보여주는 경로가 없다. 만든 사람만 자기 전시를 본다.

## Blockers

None.

## Acceptance criteria

- [x] 로그인하지 않은 사람이 전시 만들기에 들어가면 로그인을 먼저 요구받는다.
- [x] Google 계정으로 로그인하면 원래 하려던 화면으로 돌아오고, 로그인한 사용자는 로그아웃할 수 있다.
- [x] 필수 항목(사진, 물건 이름, 사연)이 비어 있으면 생성 단계로 넘어가지 못하고, 무엇이 비었는지 화면에서 알 수 있다.
- [x] 사연 입력란에 "어떻게 갖게 됐나요?"와 "왜 아직 가지고 있나요?"가 보조 질문으로 보인다.
- [x] 분위기를 고르지 않아도 기본값으로 생성된다.
- [x] 생성 결과로 제목 후보 여러 개와 설명 한 편이 나온다. 사용자는 후보 중 하나를 고르거나 제목을 직접 쓸 수 있다.
- [x] 사용자는 설명을 직접 고칠 수 있고, 설명 전체를 다시 생성할 수도 있다. 분위기를 바꿔 다시 생성하면 어느 분위기로 생성했는지 사람이 구분할 수 있는 결과가 나온다.
- [x] 사용자가 입력한 어느 항목에도 없던 구체적 사실이 생성된 문구에 사실처럼 등장하지 않는다. 사용자가 사연이나 선택 항목에 적은 사용 기간과 특징은 문구에 써도 된다.
- [x] 생성된 문구는 평범한 물건을 박물관 작품처럼 다루는 큐레이터의 어조를 유지한다.
- [x] 사용자가 아무것도 하지 않아도 사진이 기본 영역으로 전시에 실리고, 원하면 영역을 잘라 위치를 맞출 수 있다.
- [x] 미리보기와 확정 후 전시 화면이 사진 배치와 제목과 설명, 원래 사연 표시 여부와 이름·별명 표시에서 같다. 편집이나 삭제 같은 작성자 조작 UI는 비교 대상에서 제외한다.
- [x] 확정한 전시는 나만 보기 상태로 내 전시관에 남는다.
- [x] 확정 직후 사용자는 확정한 전시를 보고, 거기서 내 전시관으로 이동할 수 있다.
- [x] 내 전시관에서 새 전시 만들기로 바로 들어갈 수 있고, 전시가 여러 개면 모두 목록에 보인다.
- [x] 입력한 원래 사연을 전시에 함께 보여줄지 사용자가 선택한다. 기본값은 보여주는 것이고, 그 선택이 저장되어 미리보기와 작성자가 보는 전시 화면에 그대로 반영된다.
- [x] 전시에 표시할 이름이나 별명을 선택해서 입력할 수 있다. 입력한 값은 전시에 저장되어 미리보기와 작성자 화면에 그대로 보이고, 비워 두면 표시하지 않는다. Google 계정의 이름으로 대신 표시하지 않는다.
- [x] 나만 보기 상태의 전시는 작성자가 아닌 사람이 주소를 알아도 볼 수 없다.
- [x] 사진 접근은 그 사진이 딸린 전시의 공개 상태를 확인한 뒤에 열린다. 제작 중에 올린 사진과 나만 보기 전시의 사진은 파일 주소를 알아도 작성자가 아니면 열리지 않는다.
- [x] 작성자는 확정한 전시의 제목과 설명과 사진과 원래 사연 표시 여부와 이름·별명을 고칠 수 있고 전시를 삭제할 수 있다. 사진은 다른 사진으로 교체할 수 있고, 사진을 지운 채로는 저장할 수 없다. 다른 사람은 이 가운데 무엇도 할 수 없다.
- [x] 수정과 삭제 같은 작성자 전용 동작은 작성자에게만 화면에 나타난다.
- [x] AI는 새 문구 생성과 재생성을 요청할 때만 호출한다. 전시를 저장하거나 다시 열어 감상할 때는 AI를 호출하지 않고, 사용자가 확정한 문구를 그대로 보여준다.
- [x] 전시 화면의 첫 화면에서는 사진과 제목 등 감상 콘텐츠가 중심으로 보이고, 편집 같은 조작 UI는 그보다 약하게 보인다. 긴 설명은 스크롤해 끝까지 읽을 수 있고, 모든 내용을 한 화면에 맞추려고 축소하거나 잘라내지 않는다.
- [x] 전시가 하나도 없는 내 전시관의 빈 상태와 AI 생성 대기 상태가 화면에 정의된다.
- [x] AI 생성이 실패하면 입력한 내용이 사라지지 않고 다시 시도할 수 있다.

## Constraints

- 공개 범위를 바꾸는 경로와 공유 관련 컨트롤은 01의 화면에 두지 않는다. 확정한 전시는 나만 보기 상태로만 존재한다.
- 전시 기록은 처음부터 공개 범위 값을 갖고, 01에서는 나만 보기 값만 쓴다. 전시와 사진의 접근 제어는 그 값을 읽는 형태로 만든다. 02는 접근 정책을 새로 만드는 것이 아니라 이 값에 링크 공유 상태를 추가한다.
- 전시 화면은 하나만 만든다. 02의 방문자 화면은 이 화면을 재사용한다.
- AI 생성 실패를 다루는 수용 기준의 "실패"는 기본 경로와 대체 경로가 모두 실패한 경우를 뜻한다.
- [data-and-auth](../../../decisions/data-and-auth.md) — 로그인을 Google 계정으로만 받는 것, 작성자만 수정하고 삭제할 수 있다는 규칙, 업로드된 사진의 비공개 보관을 어디서 강제할지 정한다.
- [ai-gateway](../../../decisions/ai-gateway.md) — 문구 생성을 어느 게이트웨이로 호출하고 실패하면 어디로 넘길지 정한다.
- [ui-composition](../../../decisions/ui-composition.md) — 일반 UI는 shadcn 구성으로 만들고 전시 화면 같은 제품 고유 표면만 직접 만드는 경계, loading과 empty와 error 상태를 정상 화면과 함께 설계하는 규칙을 정한다.

## Verification

제작 흐름

- 로그아웃 상태로 전시 만들기 주소에 들어가 로그인을 먼저 요구받는지 확인하고, 로그인한 뒤 원래 하려던 화면으로 돌아오는지 확인한다. 로그아웃도 해본다.
- 필수 항목을 비운 채 생성을 시도해, 넘어가지 못하고 무엇이 비었는지 화면에서 알 수 있는지 확인한다. 사연 입력란에 보조 질문 두 개가 보이는지도 함께 확인한다.
- 분위기를 건드리지 않고 생성해 기본값으로 결과가 나오는지 확인한다.
- 제목을 후보 선택과 직접 입력 두 방식으로 각각 정해본다.
- 설명을 직접 고친 뒤 전체 재생성까지 해보고, 두 경로가 모두 동작하는지 확인한다.
- 같은 입력으로 분위기 세 가지를 각각 생성해 결과를 나란히 놓고, 어느 분위기로 생성한 것인지 사람이 구분할 수 있는지 확인한다.
- 사진 자르기를 건드리지 않고 끝까지 확정해 전시 화면이 정상으로 보이는지 확인하고, 다시 한 번은 영역을 잘라 그 영역이 미리보기와 확정된 전시 화면에 그대로 반영되는지 확인한다.
- 확정 직전 미리보기와 확정 후 전시 화면을 나란히 놓고 사진 배치와 제목과 설명, 원래 사연 표시 여부와 이름·별명 표시가 같은지 확인한다.
- 확정한 뒤 내 전시관 목록과 전시 화면에서 확정한 문구가 그대로 보이는지 확인하고, 확정 직후 화면에서 내 전시관으로 이동할 수 있는지 확인한다.
- 같은 계정으로 두 번째 전시를 만들어 내 전시관에 두 점이 함께 남는지 확인한다.
- 원래 사연을 보여주지 않기로 저장한 전시를 다시 열어 작성자 화면에도 원래 사연이 없는지 확인하고, 보여주기로 한 전시에서는 보이는지 확인한다.
- 이름·별명을 비운 경우에도 전시를 확정할 수 있고 미리보기와 저장 후 화면에 이름이 표시되지 않는지 확인한다. 입력한 경우에는 같은 값이 표시되는지 확인하고, 확정 후 값을 수정하거나 비워서 저장한 결과도 다시 열어 확인한다.

문구 품질

- 서로 다른 물건과 사연 세 건으로 생성해 결과를 눈으로 검토한다. 사용자가 입력하지 않은 사실이 섞였는지와 물건이 격상되어 읽히는지를 함께 본다. 필수 항목은 모두 채우되 사용 기간과 특징은 사연에 쓰지 않고 선택 항목에만 적은 입력 한 건을 포함해, 그 정보는 문구에 반영할 수 있는지 확인한다.
- 넓은 화면과 좁은 화면에서 첫 화면의 중심이 사진과 제목 등 감상 콘텐츠인지, 조작 UI가 그보다 약하게 보이는지 확인한다. 긴 설명을 저장해 스크롤로 끝까지 읽을 수 있고 내용이 잘리거나 과도하게 축소되지 않는지도 확인한다.

권한

- 같은 전시를 다시 열어 제목과 설명과 사진을 고치고 저장한 뒤, 고친 내용이 남는지 확인한다. 이때 전시 주소와 마지막으로 저장된 사진의 파일 주소를 적어 둔다.
- 사진을 지운 채 저장을 시도해 막히고 무엇이 비었는지 화면에서 알 수 있는지 확인한다.
- 전시가 남아 있는 상태에서, 먼저 작성자 계정으로 그 두 주소가 정상적으로 열리는지 확인해 대조군을 만든다.
- 이어서 로그아웃한 브라우저와 다른 계정으로 각각 같은 두 주소에 접근해, 두 경로 모두 열리지 않는지 확인한다.
- 다른 계정으로, 화면을 거치지 않고 남의 전시 기록을 직접 조회해 결과에 나오지 않는지 확인한다.
- 다른 계정으로 그 전시의 제목과 설명과 사진 수정, 그리고 전시 삭제를 시도해 모두 거부되는지 확인하고, 작성자로 돌아와 내용이 그대로인지 확인한다.

AI 경로

- 기본 경로(Vercel AI Gateway) 호출만 실패하는 상황을 만들어, 대체 경로(OpenRouter)로 넘어가 문구 생성이 끝까지 성공하는지 확인한다.
- 두 경로가 모두 실패하는 상황을 만들어, 입력한 내용이 남아 있고 다시 시도할 수 있는지 확인한다.
- 생성과 재생성에서만 AI 호출이 발생하는지 확인한다. 전시 확정, 문구 직접 수정 후 저장, 내 전시관 조회와 전시 다시 열기에서는 AI 호출이 발생하지 않고 확정한 문구가 유지되는지 호출 기록으로 확인한다.

마지막

- 작성자가 그 전시를 삭제하면 내 전시관 목록에서 사라지는지 확인한다.

## Execution

- Verification: Supabase 프로젝트(스키마·RLS·Storage 정책 `supabase/schema.sql` 적용, Google OAuth 연결)와 Vercel AI Gateway/OpenRouter 키를 실제로 연결한 뒤 `next dev`로 실행해 전 과정을 브라우저에서 직접 확인했다. 로그인 요구·리다이렉트·로그아웃, 필수 항목 검증과 보조 질문, 기본 분위기 생성, 분위기를 바꿔 재생성했을 때 어조가 뚜렷이 달라짐(따뜻하게 vs 유쾌하게), 사실을 지어내지 않고 큐레이터 어조를 유지하는 문구 품질, 사진 위치 조정 UI, 미리보기와 확정 화면의 일치, 확정 후 내 전시관 이동, 전시 두 개 동시 목록 노출, 사연 표시 여부·표시 이름의 저장과 반영, 수정·삭제(작성자 전용 노출 포함), 빈 상태와 생성 대기 상태 UI를 모두 실제 화면에서 확인했다. 권한 검증은 로그인된 실제 세션 토큰으로 REST API를 직접 호출해 익명 요청이 나만 보기 전시의 조회·서명 URL 발급·수정·삭제 모두에서 차단됨을 확인했고, `photo_path`를 비우려는 시도는 DB NOT NULL 제약으로 거부됨을 확인했다. AI 경로는 기본 경로만 깨뜨려 대체 경로(OpenRouter)로 성공하는 경우와, 두 경로를 모두 깨뜨려 입력(사진·물건 이름·사연)이 보존된 채 재시도 가능한 경우를 모두 실제로 재현해 확인했다. AI 호출은 생성/재생성에서만 발생하고 확정·조회·재방문에서는 발생하지 않음을 서버 로그로 확인했다. `bun run typecheck`, `bun run lint`(레포에 이미 있던 무관한 eval fixture 오류 제외), `bun run test` 모두 통과. 넓은/좁은 뷰포트에서 사진·제목 중심 레이아웃과 옅은 조작 버튼 배치를 스크린샷으로 확인했다.
