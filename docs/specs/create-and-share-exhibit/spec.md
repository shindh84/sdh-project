# 전시 한 점 만들어 공유하기

## 사용자에게 보이는 결과

로그인한 사람이 물건 사진과 짧은 사연을 건네면 AI가 전시 제목 후보와 설명을 제안한다. 사용자가 그 문구를 고쳐 확정하면 전시 한 점이 내 전시관에 남는다. 원하면 링크를 만들어 친구에게 보내고, 링크를 받은 사람은 로그인 없이 그 전시를 감상한다.

앱 전체의 premise는 [PRODUCT.md](../../../PRODUCT.md)에 있다. 이 작업은 그중 핵심 루프의 한 바퀴를 처음으로 완성한다.

## 승인된 범위

포함하는 것

- 로그인
- 전시 제작 흐름: 입력, AI 문구 생성, 편집, 미리보기, 확정
- 내 전시관: 내가 만든 전시가 모이는 목록
- 공개 범위 두 가지: 나만 보기와 링크로 공유
- 작성자의 전시 수정과 삭제
- 전시에 표시할 이름이나 별명 선택 입력
- 링크 방문자의 감상 화면

포함하지 않는 것

- 모두에게 공개와 전시 둘러보기. `PRODUCT.md`가 제품 방향에는 포함하지만 이 작업 뒤로 미룬 경험이다.
- 여러 전시를 주제별로 묶고 순서를 정하는 기획전
- 전시 카드 이미지 저장, 오디오 도슨트
- AI가 사진을 분석해 색이나 흠집을 문구에 반영하는 것. `PRODUCT.md`는 사진도 감상의 중심으로 두지만 첫 버전에서는 미룬다. 여기서 사진은 전시 화면에 배치만 한다.
- 설명을 문장 단위로 나눠 고른 문장만 다시 생성하는 것

## 사용자가 입력하는 것

| 항목 | 필수 여부 |
|---|---|
| 물건 사진 한 장 | 필수 |
| 물건 이름 | 필수 |
| 사연 한두 문장 | 필수 |
| 전시 문구 분위기 | 기본값 제공 |
| 사용 기간과 특별한 특징 | 선택 |
| 전시에 표시할 이름이나 별명 | 선택, 비워 두면 표시하지 않음 |

## 수용 기준

1. 로그인하지 않은 사람이 전시 만들기에 들어가면 로그인을 먼저 요구받는다.
2. Google 계정으로 로그인하면 원래 하려던 화면으로 돌아오고, 로그인한 사용자는 로그아웃할 수 있다.
3. 필수 항목이 비어 있으면 생성 단계로 넘어가지 못하고, 무엇이 비었는지 화면에서 알 수 있다.
4. 사연 입력란에 "어떻게 갖게 됐나요?"와 "왜 아직 가지고 있나요?"가 보조 질문으로 보인다.
5. 분위기를 고르지 않아도 기본값으로 생성된다.
6. 생성 결과로 제목 후보 여러 개와 설명 한 편이 나온다. 사용자는 후보 중 하나를 고르거나 제목을 직접 쓸 수 있다.
7. 사용자는 설명을 직접 고칠 수 있고, 설명 전체를 다시 생성할 수도 있다. 분위기를 바꿔 다시 생성하면 어느 분위기로 생성했는지 사람이 구분할 수 있는 결과가 나온다.
8. 사용자가 입력하지 않은 구체적 사실이 생성된 문구에 사실처럼 등장하지 않는다. 구매 연도, 선물한 사람, 장소, 가격처럼 사용자가 입력한 어느 항목에도 없던 정보를 지어내지 않는다. 사용자가 사연이나 선택 항목에 적은 사용 기간과 특징은 문구에 써도 된다.
9. 생성된 문구는 평범한 물건을 박물관 작품처럼 다루는 큐레이터의 어조를 유지한다.
10. 사용자가 아무것도 하지 않아도 사진이 기본 영역으로 전시에 실리고, 원하면 영역을 잘라 위치를 맞출 수 있다.
11. 미리보기와 확정 후 전시 화면이 사진 배치와 제목과 설명, 원래 사연 표시 여부와 이름·별명 표시에서 같다. 편집이나 삭제 같은 작성자 조작 UI는 비교 대상에서 제외한다.
12. 확정한 전시는 나만 보기 상태로 내 전시관에 남는다.
13. 확정 직후 사용자는 확정한 전시를 보고, 거기서 내 전시관으로 이동할 수 있다.
14. 내 전시관에서 새 전시 만들기로 바로 들어갈 수 있고, 전시가 여러 개면 모두 목록에 보인다.
15. 입력한 원래 사연을 전시에 함께 보여줄지 사용자가 선택한다. 기본값은 보여주는 것이다.
16. 사용자가 링크 공유를 켜면 링크가 생기고, 링크를 받은 사람은 로그인 없이 그 전시를 본다. 공유를 끄면 같은 링크로 더 이상 볼 수 없다. 링크를 모르는 다른 사용자가 남의 전시를 찾아볼 수 있는 경로는 이 작업에 없다.
17. 공유를 껐다가 다시 켜면 예전에 나눠준 링크가 같은 전시를 다시 연다. 링크는 전시에 묶여 있고 공개 상태만 바뀐다.
18. 나만 보기 상태의 전시는 작성자가 아닌 사람이 주소를 알아도 볼 수 없다.
19. 사진은 업로드한 순간부터 비공개로 보관된다. 제작 중인 사진과 공유한 적 없는 나만 보기 전시의 사진은 파일 주소를 알아도 작성자가 아니면 열리지 않는다. 관람자용 사진 주소는 서비스가 전시의 현재 공개 상태를 확인한 뒤에만 발급하며 발급 후 최대 5분 동안 유효하다. 공유 해제가 완료되면 관람자의 전시 접근과 새 사진 주소 발급을 즉시 차단한다. 기존 주소에 대한 후속 요청도 서비스·CDN 캐시를 포함해 해제 완료 후 최대 5분 안에 차단된다.
20. 작성자는 확정한 전시의 제목과 설명과 사진과 공개 범위와 원래 사연 표시 여부와 이름·별명을 고칠 수 있고 전시를 삭제할 수 있다. 사진은 다른 사진으로 교체할 수 있다. 확정된 전시에는 언제나 사진 한 장이 있어야 하므로 사진을 지운 채로는 저장할 수 없다. 다른 사람은 이 가운데 무엇도 할 수 없다.
21. 제목과 설명과 사진과 이름·별명을 고쳐도 이미 나눠준 공유 링크는 같은 전시를 계속 가리킨다.
22. 공유 중인 전시를 삭제하면 관람자는 기존 공유 링크로 전시를 볼 수 없고 새 관람자용 사진 주소도 발급받을 수 없다. 두 접근은 삭제 완료 즉시 차단한다. 이미 발급된 사진 주소에 대한 후속 요청은 공유 해제와 같은 기준으로, 서비스·CDN 캐시를 포함해 삭제 완료 후 최대 5분 안에 차단된다.
23. AI는 새 문구 생성과 재생성을 요청할 때만 호출한다. 전시를 저장하거나 다시 열어 감상할 때는 AI를 호출하지 않고, 사용자가 확정한 문구를 그대로 보여준다.
24. 전시 화면의 첫 화면에서는 사진과 제목 등 감상 콘텐츠가 중심으로 보이고, 편집이나 공유 같은 조작 UI는 그보다 약하게 보인다. 긴 설명은 자연스럽게 스크롤해 끝까지 읽을 수 있다. 사진·제목·설명 전체를 한 화면에 맞추기 위해 축소하거나 잘라내지 않는다.
25. AI 생성이 실패하면 입력한 내용이 사라지지 않고 다시 시도할 수 있다. 여기서 실패는 기본 경로와 대체 경로가 모두 실패한 경우를 뜻한다.
26. 전시에 표시할 이름이나 별명은 선택 입력이다. 입력한 값은 전시에 저장되어 미리보기와 작성자·관람자 화면에 그대로 보인다. 비워 두면 표시하지 않으며, Google 계정의 이름으로 대신 표시하지 않는다.

## 확정된 제약과 근거

- 첫 버전부터 로그인을 둔다. `PRODUCT.md`의 핵심 루프가 "확정한 전시가 내 전시관에 남는다"이고 가장 중요한 성공 신호가 "권유 없이 두 번째 전시를 만드는가"인데, 로그인이 없으면 브라우저를 바꾸는 순간 전시가 사라져 그 신호를 관찰할 수 없다.
- 공개 범위의 기본값은 나만 보기다. 사연이 개인적일수록 아무에게도 보여주지 않아도 된다는 안전장치가 솔직한 입력을 끌어낸다.
- 로그인은 Google 계정으로만 받는다. 앱을 여는 계기가 정리하다 물건을 발견한 짧은 순간이라 회원가입 폼과 인증 메일이 끼면 그 자리에서 이탈한다. 비밀번호를 직접 받으면 재설정과 메일 인증까지 따라붙어 첫 버전 범위가 커진다.
- 사진은 기본이 비공개다. 사진은 전시를 확정하기 전에 이미 업로드되므로 저장 시점부터 비공개로 두고, 서비스가 공개 상태를 확인한 뒤에만 관람용 접근을 연다. 공개 범위를 전시 기록에만 걸고 사진 파일을 열어두면 주소를 아는 사람에게 비공개 전시가 그대로 새어 나간다.
- 공유 해제와 전시 삭제의 사진 접근 차단 시점은 `data-and-auth` 계약을 따른다. 기존 주소에만 최대 5분의 유예를 허용하고, 새 관람자용 주소 발급은 즉시 막는다. 이미 사용자 기기에 내려받은 사진의 회수는 포함하지 않는다.
- 확정된 전시에는 언제나 사진이 있다. 수용 기준 10번과 24번, `PRODUCT.md`의 관람 정의가 모두 사진의 존재를 전제하므로, 사진 지우기는 새 사진으로 교체하는 과정의 중간 동작으로만 둔다.
- 공유 링크는 전시에 묶인다. 공유를 껐다 켜도 같은 링크가 같은 전시를 가리킨다. `PRODUCT.md`가 링크를 전시에 딸린 것으로 다루고, 전시 주소와 공유 주소를 따로 두면 화면과 접근 정책이 한 겹 늘어난다. 되돌릴 수 없는 차단이 필요해지면 그때 다시 본다.
- 제작 도중의 입력은 저장하지 않는다. 전시를 확정해야 전시가 만들어지고, 확정하지 않고 떠나면 입력한 내용은 남지 않는다. 초안 상태를 두면 초안 목록과 이어쓰기와 정리 규칙이 통째로 따라붙어 첫 버전 범위가 크게 늘어난다. 다만 사진 파일은 확정 전 업로드 시점에 이미 저장소에 올라가 있다.
- 설명은 전체 재생성과 직접 편집으로 고친다. 사용자가 원하는 결과에 닿는 경로가 이미 두 개이고, 문장 단위 재생성은 문장 경계 관리와 나머지 문장과의 톤 일치가 따라붙어 첫 버전 범위를 크게 늘린다.
- AI는 사용자가 입력한 내용을 표현으로 다듬을 뿐 사실을 더하지 않는다. 지어낸 사실이 섞이면 "내 이야기"라는 전제가 무너지고, 그것이 이 제품이 주는 가치의 전부다.
- 사용자 데이터와 인증과 사진 저장은 [data-and-auth](../../decisions/data-and-auth.md) 계약을 따른다. 수용 기준 18번과 20번의 기록 접근 제한은 이 계약이 DB의 행 수준 접근 제어로 정한다. 19번과 22번의 사진 접근은 이 계약이 공개 상태 확인, 신규 주소 발급 차단, 기존 주소의 최대 5분 유효기간을 정한다. 이를 만족하는 접근 경로와 캐시 설정은 구현에서 정한다.
- 문구 생성 호출은 [ai-gateway](../../decisions/ai-gateway.md) 계약을 따른다. 어떤 게이트웨이를 기본으로 쓰고 실패 시 어디로 넘길지 이 계약이 정한다.
- 화면 구성은 [ui-composition](../../decisions/ui-composition.md) 계약을 따른다. 일반 UI는 shadcn 구성을 쓰고, 전시 화면처럼 제품의 성격을 드러내는 표면은 직접 만들 수 있다.

## 가정

아래는 바꾸기 쉬운 기본값이다. 구현 중 어긋나면 그 자리에서 뒤집어도 된다.

- 분위기 선택지는 유쾌하게, 따뜻하게, 진지한 큐레이터처럼 세 가지이고 기본값은 따뜻하게다.
- 제목 후보는 세 개를 제안한다.
- 문구 생성에는 Claude Sonnet 계열 모델을 쓴다. 정확한 모델 식별자는 구현 시점의 Vercel AI Gateway 문서에서 확인한다.
- 배포는 Vercel을 쓴다. 기본 AI 게이트웨이가 Vercel이고 프로젝트가 Next.js라 자격증명과 배포가 한 울타리에서 끝난다. 이 값을 뒤집으면 `ai-gateway` 계약이 기본 경로를 고른 근거가 사라지므로 그 계약을 함께 다시 본다.

## 미룬 결정

- 확정하지 않고 떠난 사용자가 올린 사진 파일을 언제 정리할지 정하지 않았다. 그때까지는 그 파일이 비공개 상태로 저장소에 남는다.
- 삭제하거나 교체한 사진의 파일을 저장소에서 언제 실제로 지울지 정하지 않았다. 물리적인 파일 정리 시점과 별개로, 관람자 접근은 `data-and-auth` 계약의 신규 주소 발급 및 기존 주소 유효기간 규칙을 지켜야 한다.
- 한 사람이 만들 수 있는 전시 수와 사진 용량의 상한을 정하지 않았다.

## 남은 위험

- 입력을 저장하지 않으므로, 사진 업로드부터 편집까지 한 번에 끝내지 못한 사용자는 입력을 잃는다. 제작 흐름이 예상보다 길면 첫 전시 완성률이 떨어질 수 있다.
- 수용 기준 8번과 9번은 생성 결과를 눈으로 확인해야 판단할 수 있다. 사용자가 입력하지 않은 사실이 섞이는지, 문구가 물건을 격상시켜 읽히는지를 실제 입력 몇 건으로 확인해야 하며 자동 검사로 완전히 보장하기 어렵다.
- 나만 보기는 막고 링크 공유는 여는 규칙을 전시 기록과 사진 파일 두 경로에서 함께 지켜야 한다. 링크 방문자는 로그인하지 않은 상태로 들어오므로, 작성자와 링크 방문자와 아무 관계 없는 사람 세 경우를 구현에서 모두 확인해야 한다.
